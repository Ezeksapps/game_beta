PLAN FOR MOVEMENT IMPLEMENTATION
--------

Movement is dealt with one tile at a time (Z axis only considered when detecting collision, else ignored and world treated as 2D)
The translation is turned into a transform matrix which is multiplied by the model matrix to get the new model matrix

However, the translation is not instant. All movement also plays an animation (ANIM_EVENT_WALK) via the sprite sheet system
One complete instance of the animation needs to play to move one tile in any direction. The translation of the sprite billboard
needs to move smoothly as that animation plays, moving in small incremental steps every frame the animation plays until arriving at the
final position when the animation ends. If another invokation of Entity::move() occurs, then this repeats. Otherwise, the entity stops moving
and goes to the idle state (ANIM_EVENT_IDLE)

So, to do this, find the total number of frames the animation plays for (loop through m_pActiveSprite->frameDurations and sum all values)
This will be the number of smaller translations that will be applied to this entity (one per frame)
The transform matrix applied every step will always be the same, since these steps are all equally sized.
To find the translation vector, do:
vec3 translVec = vec3(dx / animFrames, dy / animFrames, 0.0f /* Z-axis ignored */);

Then form the transform matrix from this.
The Renderer needs to now be signalled to start the translations for the required number of frames, but class Entity cannot access
Renderer. (Since the doesn't make sense) So, like for sprite sheet animation switching, add a callback to Entity that the renderer can
attach a function to. The callback runs whenever Entity calls it an invokes the function inside the renderer allowing it to process the transformation

UPDATE:
Model matrix is calculated on every update() call, transform matrix can auto form, tranlVec is all that's needed for callback
